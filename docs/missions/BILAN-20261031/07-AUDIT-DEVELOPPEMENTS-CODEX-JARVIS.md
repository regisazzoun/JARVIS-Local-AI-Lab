# Audit rétrospectif des développements

| ID | Fonction | Classe | Analyse du contrat | Décision proposée |
|---|---|---|---|---|
| DEV01 | Mission Engine / MissionStore | A | Objectifs, plans, événements, preuves et reprise canonique propres à JARVIS. LangGraph/Temporal couvrent persistance et reprise, pas le contrat complet de preuves et acteurs du laboratoire. | conserver ; réduire progressivement orchestration générique |
| DEV02 | Ledger des trois cycles | B | États observés et compteur stable par problème, avec résultat inconnu et interdiction du doublon. Temporal RetryPolicy offre des retries, mais un maximum de tentatives ne distingue pas correction fonctionnelle et transport. | garder le contrat métier ; réutiliser le transport standard |
| DEV03 | Budget et compaction de contexte | C | Budget et archivage existent dans plusieurs chemins. Qwen Code possède sa gestion de session et de contexte ; sa version installée et ses patches restent à comparer, pas la documentation latest seule. | unifier mesure et garde ; ne pas supprimer les compteurs P2 |
| DEV04 | Registre d’outils / deux transports MCP | B | Contrats centraux puis adaptateurs stdio et clients. SDK MCP standard déjà utilisé ; deux surfaces ne sont pas automatiquement deux moteurs. | générer les catalogues depuis le même registre |
| DEV05 | Skill Lab | A | Versions immuables, activation, reçus de test et compétences métier. Skills Qwen Code couvrent instructions et scripts, pas les mêmes garanties de réception du Skill Lab. | conserver ; réutiliser les formats standards quand compatibles |
| DEV06 | Broker root / politique / identité | A | Permissions persistantes, identité exacte des hôtes et secrets hors modèle. OpenSSH/Ansible fournissent le transport déjà réutilisé ; ne remplacent pas la politique propriétaire. | garder la frontière ; éviter un transport SSH parallèle |
| DEV07 | Inventaires et sondes système | C | Plusieurs sondes shell/Python formatent CPU/GPU et mémoire. ansible.builtin.setup et nvidia_gpu_exporter existent ; GPU/PID demandent un complément. | normaliser unités/types et réutiliser des collecteurs |
| DEV08 | Qwen Code et Goal | B | Agent OSS installé ; relais Ollama, limites et permissions adaptés par Codex. Qwen Code natif fournit fichiers, tests, sessions et Goal. Aucun Goal générique supplémentaire nécessaire. | réduire patches au strict nécessaire, tester compatibilité versionnée |
| DEV09 | WebUI / Apache / Tailscale | B | Produits existants intégrés ; pas une interface développée entièrement par Codex. Open WebUI fournit chat/historique/outils ; Apache et Serve fournissent proxy/HTTPS. | conserver une instance ; profil explicite pour JARVIS canonique |
| DEV10 | Connecteur Google et OAuth | B | Serveur Workspace amont ; isolation des comptes, callback et deux fonctions Sheets ajoutés. MCP amont possède OAuth et trente méthodes retenues ; API Google sont des services Google, pas du code Codex. | conserver l’amont ; vérifier les deux ajouts et ne pas les attribuer à l’éditeur |
| DEV11 | Deux chemins Google | D | Ancien chemin BYOC maintenu et nouveau chemin OAuth fourni. Le nouveau répond aux comptes reçus ; ancien token valide peut encore être utile. | déprécier seulement après inventaire des consommateurs ; aucune suppression ici |
| DEV12 | GitHub | B | CLI gh existante, enveloppe de permissions et vérification des contenus. API GitHub et serveur MCP officiel existent ; ils ne garantissent pas les restrictions de branches identiques. | réutiliser gh/MCP ; conserver garde publication et lecture après écriture |
| DEV13 | Mémoire et stockage d’interface | D | WebUI a son historique ; mémoire JARVIS reste canonique pour son moteur. Deux historiques ne prouvent pas deux mémoires canoniques synchronisées. | rendre le chemin explicite, lier par références ; pas de migration automatique |
| DEV14 | Rapports et validation sémantique | A | Provenance, faits fermés et relevé déterministe propres aux preuves JARVIS. Pydantic/JSON Schema valident les formes, pas la vérité de la prose. | conserver faits déterministes ; prose toujours qualifiée |
| DEV15 | Surveillance timers / GPU | E | Santé et télémétrie installées ; diagnostic agentique complet P7 non reçu. systemd redémarre les processus ; exporter Prometheus expose les mesures ; aucun ne prouve seul la reprise métier. | réutiliser collecte/restart ; petit adaptateur incident vers moteur existant |
| DEV16 | JL-03 | A | Orbe, console de preuves, télémétrie et expérience propriétaire spécifiques. Open WebUI recouvre conversation, fichiers, historique et outils ; pas forcément le flux de preuves/orbe demandés. | comparer module par module ; pas de remplacement global immédiat |

A : spécifique indispensable ; B : adaptateur pertinent ; C : fonction générique redéveloppée ; D : recouvrement ou redondance ; E : fonction incomplète. Une ligne regroupe un domaine fonctionnel, pas un fichier. Les classes C/D identifient un potentiel à instruire, pas une équivalence déjà prouvée ou une autorisation de remplacement.

Attribution : l’amont Qwen Code, Open WebUI, Ollama, MCP, Ansible, SQLite, Apache, Tailscale, Whisper/Piper n’a pas été développé par Codex/JARVIS. Codex a fourni l’essentiel du code d’intégration et des contrôles ; JARVIS a produit config-repair et des programmes/corrections tracés dans les missions antérieures. Les auteurs Git configurés ne prouvent pas à eux seuls l’agent réel : les rapports d’attribution et reçus sont nécessaires. L’essai de ce bilan est Qwen Code guidé, pas une nouvelle mission autonome distribuée.

Six des 51 modules Python installés diffèrent de cette branche : worker, durable_tools, mission_store, mission_assurance, missions, tools. Comparaison SHA dans preuves/local.json. Les rapports antérieurs documentent des adaptations runtime conservant des ajouts historiques. Cet écart est un risque de reproductibilité ; il ne prouve pas à lui seul un défaut de fonctionnement ou une version chargée en mémoire. Aucun fichier actif n’a été remplacé.
